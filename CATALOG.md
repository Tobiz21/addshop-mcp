# Управление товарами через Addshop MCP

## Создание полного товара

`addshop_build_product` принимает единую specification:

- `fields`: название, описания, категория, производитель, SEO, габариты и цена;
- `offer`: цена, артикул, остаток, размер, цвет, бесконечный остаток;
- `properties`: характеристики;
- `image_paths`: до 20 файлов из `ADDSHOP_UPLOAD_ROOT`;
- `publish`: публиковать ли после полной проверки.

Первый вызов с `apply=false` возвращает `plan_hash` и последовательность шагов.
Apply принимается только с точным hash. Товар сначала настраивается как скрытый,
потом создаются предложение, характеристики и изображения, выполняется проверка,
и только последним шагом возможна публикация с `confirm_publish=true`.

Если промежуточный шаг завершается ошибкой, MCP пытается оставить созданный товар
неопубликованным и сохраняет recovery journal с его ID. Автоматического удаления
нет, поскольку `/delete/` в Addshop необратимо изменяет данные уже при GET.

## Чертёж и сравнение товаров

`addshop_product_blueprint` извлекает безопасную specification существующего
товара: поля, основной вариант и характеристики. Публикация всегда выключена,
служебные поля не копируются, изображения возвращаются только как ссылки.

Перед созданием копии обязательно измените название, slug, артикул, штрихкод и
SEO. `addshop_compare_products` показывает различия двух карточек по полям,
основному варианту, характеристикам и количеству изображений.

`addshop_clone_product` объединяет blueprint и безопасный builder в одну
операцию. Требуется новое `field_overrides.title`; исходные slug, штрихкод и
артикулы не копируются, если их явно не задать в overrides. Характеристики можно
перенести флагом `copy_properties`, а фотографии принимаются только как явно
разрешённые локальные `image_paths` — удалённые изображения источника возвращаются
для справки, но автоматически не скачиваются.

Preview возвращает одновременно `source_revision` и `plan_hash`. Apply требует
оба точных значения, повторно читает источник и создаёт карточку скрытой. Возможная
публикация выполняется последним шагом и требует `confirm_publish=true`.

## CSV

`addshop_export_products_csv` создаёт локальный UTF-8 CSV и SHA-256. Каждая строка
содержит ID и revision. Изменять можно существующие товары и только точный набор
столбцов из экспорта.

`addshop_import_products_csv` принимает файл только из `ADDSHOP_UPLOAD_ROOT`,
ограничивает размер 5 MiB и пачку 50 товарами, блокирует дубли ID и формульные
значения. Изменившийся после экспорта товар отклоняется. Apply требует точный
plan hash неизменившегося файла, использует пакетный rollback и отдельно
подтверждает публикацию.

Для вариантов существует отдельная пара `addshop_export_offers_csv` и
`addshop_import_offers_csv`. Файл содержит product ID, offer ID, revision,
артикул, цену, остаток, размер, цвет и infinite stock. Экспорт допускает до 2000
вариантов, один импорт — до 200 существующих вариантов.

Импорт требует точный заголовок, проверяет формульные значения, дубли пар
product/offer, принадлежность варианта товару, SHA-256 файла, revision каждого
товара и `plan_hash`. Рискованные изменения используют `confirm_sensitive=true`.
Запись выполняется через общий offer batch, поэтому при ошибке применяется
обратный rollback уже изменённых полей. Создание и удаление вариантов через CSV
не выполняется.

## Отбор товаров

`addshop_catalog_taxonomy` возвращает полные пути категорий и справочники
производителей, размеров и цветов. Одновременно выявляются осиротевшие категории,
циклы родителей и повторяющиеся slug — их следует исправить до массового переноса.

`addshop_select_products` поддерживает фильтры:

- `ids`: точный список ID;
- `title_contains`: часть фактического названия из карточки;
- `category_id`;
- `manufacturer_id`;
- `active`: опубликован/скрыт.
- `price_min`, `price_max`: диапазон основной цены.

Результат содержит текущую цену, категорию, производителя, состояние публикации
и revision каждой карточки.

Перед записью `addshop_validate_product_changes` проверяет обязательное название,
slug, неотрицательные цены/габариты, числовые ID и максимальные длины. Длинные
SEO title/description возвращаются как предупреждения, а не молча сохраняются.

`addshop_suggest_product_slug` транслитерирует русское/латинское название и
проверяет занятость slug во всём каталоге, добавляя безопасный числовой суффикс.

## Массовое редактирование карточек

`addshop_bulk_edit_products` поддерживает:

- `set`: точные значения разрешённых полей;
- `price_percent`: изменение основной цены от −100% до +1000%;
- `price_rounding`: `none`, до целого или до десятков;
- `title_prefix`, `title_suffix`;
- `seo_title_template`, `seo_description_template`;
- `flags`: `show_on_main`, `bestseller`, `novelty`, `recommend`, `under_the_order` как true/false;
- `extra_category_ids`: список дополнительных категорий без внутренней checkbox-сериализации;
- `replace_text`: буквальный поиск и замена в названии, описаниях, SEO, артикуле
  или штрихкоде; для каждого поля задаются `find`, `replace`, `case_sensitive`;
- `publish`.

Шаблоны понимают `{id}`, `{title}`, `{price}`, `{vendor_code}`, `{category_id}`.
Поиск и замена не исполняет регулярные выражения и не допускает пустой строки
поиска. Конфликтующие операции над одним полем блокируются до preview.

Пример preview:

```json
{
  "selector": {"category_id": 12, "active": false},
  "transform": {
    "price_percent": 7.5,
    "seo_title_template": "{title} — купить в магазине",
    "set": {"manufacturer_id": 4}
  },
  "apply": false
}
```

Для apply необходимо без изменений передать `expected_revisions`, полученный из
preview. Если хотя бы одна карточка изменилась, вся операция блокируется до нового
preview. При ошибке после начала записи завершённые карточки откатываются в
обратном порядке. Recovery journal сохраняется локально.

Preview отдельно сообщает `matched`, `changed` и `unchanged`. Карточки без
фактического diff не включаются в revisions и не получают POST-запрос; полностью
пустая операция завершается как проверенный no-op без записи и журнала восстановления.

Публикация требует `confirm_publish=true`. Один запуск ограничен 100 товарами.

## Цены вариантов

Основная цена карточки и цены вариантов — разные данные. `price_percent` меняет
только `default_price`. Для вариантов используется `addshop_bulk_edit_offer_prices`.
Он:

- рассчитывает каждую новую цену с округлением до копеек;
- ограничен 50 товарами и 500 вариантами;
- требует exact `expected_revisions` из preview;
- требует `confirm_large_change=true` для изменения больше 50%;
- откатывает уже изменённые варианты при ошибке.

`addshop_add_offer` создаёт ровно один пустой вариант и возвращает его ID. После
этого поля заполняются через update offer. Удаление варианта отключено.

`addshop_bulk_reprice_offers` покрывает более сложные сценарии цен вариантов:

- `set` задаёт одну цену, `add` прибавляет сумму, `percent` меняет процентом;
- `rounding`: без округления, до целого или до десятков;
- `min_price` и `max_price` ограничивают итоговый диапазон;
- preview показывает цену каждого варианта и отмечает изменение свыше 50%;
- крупное изменение требует `confirm_large_change=true`;
- apply требует exact revisions и откатывает уже записанные варианты при ошибке.

Один запуск ограничен 50 товарами и 500 вариантами. Отрицательная итоговая цена
никогда не отправляется: до применения границ она ограничивается нулём.

## Массовые артикулы вариантов

`addshop_bulk_update_offer_skus` формирует артикулы по шаблону. Доступны
`{product_id}`, `{offer_id}`, `{existing}` и сквозной `{sequence}`. Preview:

- показывает старый и новый артикул каждого варианта;
- ищет регистронезависимые дубли внутри плана и во всём текущем каталоге;
- возвращает exact revisions по выбранным товарам;
- отмечает замену уже заполненных артикулов.

Apply блокируется при любом дубле. Перезапись непустых артикулов требует
`confirm_overwrite=true`; частично выполненная пачка откатывается в обратном
порядке. Шаблон и итоговый артикул ограничены 100 печатными символами.

## Неоднородное пакетное редактирование вариантов

`addshop_batch_update_offers` принимает до 200 разных вариантов и до 500
изменяемых полей. Для каждого варианта можно передать свой набор `changes`:
`vendor_code`, `price`, `quantity`, `size_id`, `color_id`, `infinitely`.

Инструмент проверяет принадлежность варианта товару, уникальность каждой пары
product/offer, типы и диапазоны значений. Preview возвращает плоский diff и exact
revision каждого затронутого товара. Изменение цены более чем на 50%, обнуление
остатка и переключение бесконечного остатка требуют `confirm_sensitive=true`.
При ошибке все уже выполненные изменения откатываются в обратном порядке.

## Матрица размеров и цветов

`addshop_product_variant_matrix` — read-only диагностика вариантов одной карточки.
Она возвращает названия размеров/цветов, комбинацию каждого варианта, цену,
артикул, остаток, infinite stock, сумму конечных остатков и их розничную стоимость.

Диагностика выявляет неизвестные ID справочников, пустые и повторяющиеся артикулы,
неположительные цены и дубли комбинаций размер/цвет. Необязательный список
`desired_combinations` показывает недостающие и лишние пары. Это только план:
недостающие варианты не создаются автоматически, поскольку безопасного удаления
ошибочно созданного варианта пока нет.

## Массовые остатки

`addshop_bulk_edit_offer_stock` работает со всеми вариантами выбранных товаров:

- `set` устанавливает точный остаток;
- `add` прибавляет или вычитает величину, не опуская результат ниже нуля;
- preview возвращает каждое исходное и новое значение;
- apply требует exact revisions;
- обнуление существующего остатка требует `confirm_zero_stock=true`;
- при ошибке уже обработанные варианты откатываются.

`addshop_inventory_replenishment_report` формирует read-only план закупки по той
же выборке товаров. Параметры задают порог низкого остатка и целевой уровень.
Отчёт разделяет нулевые и низкие остатки, исключает infinite stock, показывает
рекомендуемое количество пополнения и его ориентировочную стоимость по текущей
розничной цене. Отрицательные и нечисловые значения выводятся как проблемы и не
скрываются. Сам отчёт никогда не меняет остатки.

## Матрица и массовое изменение характеристик

`addshop_product_property_matrix` строит read-only матрицу характеристик выбранных
товаров: справочник ID и названий, значения каждой карточки, ID экземпляра
характеристики и индекс уникальных значений. Это позволяет сначала увидеть
реальную заполненность и варианты написания без догадок о внутренних ID.

`addshop_bulk_update_existing_property` меняет одно значение характеристики во
всех выбранных карточках, но только там, где характеристика уже существует:

- preview возвращает старое/новое значение и `expected_revisions`;
- товары без характеристики перечисляются отдельно и не модифицируются;
- apply принимает только точную карту revisions из последнего preview;
- при ошибке уже изменённые значения откатываются в обратном порядке;
- пустые значения и строки длиннее 100 символов блокируются.

Массовое создание отсутствующих характеристик намеренно отключено: Addshop не
даёт проверенного обратимого удаления ошибочно созданного экземпляра.

## Медиа и видео

Фотографии загружаются только из `ADDSHOP_UPLOAD_ROOT`. После загрузки
`addshop_set_product_image_color` может привязать изображение к цвету варианта.
Операция проверяет принадлежность image ID товару и повторно читает результат.

Для видео используется действие `add_video`, затем `update_video` с полученным ID.
Удаление изображений и видео остаётся отключённым.

`addshop_batch_upload_product_images` предварительно проверяет 1–20 локальных
изображений: разрешённый корень, MIME, размер до 10 MiB каждый, общий объём до
100 MiB, отсутствие повторов и SHA-256 содержимого. Preview возвращает общий
`plan_hash`; apply повторно проверяет хеш каждого файла непосредственно перед
загрузкой и читает новую revision перед каждым запросом.

Поскольку удаление изображений отключено, batch не обещает автоматический
rollback. После каждого успешного файла сохраняется recovery journal с ID новых
изображений. При частичной ошибке операция останавливается и возвращает `run_id`
для ручной проверки, не повторяя и не удаляя уже загруженные файлы.

`addshop_batch_set_product_image_colors` привязывает до 100 уже существующих
изображений к цветам. Он проверяет принадлежность image ID товару и наличие цвета
в справочнике, исключает повтор image ID, возвращает единый preview и требует
exact revision. Очистка существующей привязки требует `confirm_clear=true`.
В отличие от загрузки, изменение color ID обратимо: при ошибке выполненные
привязки откатываются в обратном порядке.

## Аудит качества

`addshop_product_quality_audit` проверяет:

- описание и SEO;
- фотографии;
- варианты и нулевые цены;
- остатки;
- характеристики;
- отсутствие артикулов;
- дубли артикулов между вариантами.

Аудит read-only и может использовать тот же selector.

`addshop_duplicate_product_audit` отдельно группирует повторы нормализованных
названий, slug, штрихкодов и артикулов вариантов.

`addshop_catalog_dashboard` агрегирует публикации, диапазон и среднюю цену,
варианты, изображения, остатки, распределение категорий/производителей и
ориентировочную розничную стоимость конечных остатков. Бесконечные остатки в
стоимость не включаются.

## Рекомендуемый рабочий процесс

1. Выбрать товары и проверить количество.
2. Создать snapshot с SHA-256.
3. Запустить quality audit.
4. Получить preview массового изменения.
5. Проверить diff и список ID.
6. Передать exact revisions и применить.
7. Сравнить магазин со snapshot.
8. Проверить audit log и несколько карточек вручную.
